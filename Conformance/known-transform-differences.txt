# -- this library's own gaps, still to be closed ------------------------------------------------
#
# These are defects here, not there.  They are listed so the suite stays honest about what it is and
# is not checking, and each one is a piece of work rather than a decision.

# Sixteen bit gamma, where the reference deliberately works at reduced precision.
#
# A table over sixteen bit samples would need 65536 entries per image, so the reference does not build
# one.  It builds a coarser table instead and looks samples up in it, which loses the low bits on
# purpose.  How coarse depends on the image: the significant-bits chunk saying fewer than sixteen bits
# makes it coarser, and asking to narrow the samples to eight afterwards makes it coarser still, since
# precision that is about to be discarded is not worth keeping.
#
# This library computes each sixteen bit sample exactly instead.  That agrees with the reference
# wherever its table happens to be at full precision — which is every sixteen bit image here that has
# no significant-bits chunk and is not being narrowed — and differs by a bit or two elsewhere.
#
# So the two lists below are exactly the cases where the reference's table is coarse: one image with a
# significant-bits chunk, and the narrowing combinations on the others.
#
# Closing this means reproducing the coarse table rather than improving on it, since the goal is to
# agree rather than to be more accurate.
#
# Part of it has been recovered.  Every one of the sixty five thousand sixteen bit values was put
# through both libraries with a correction applied and the samples narrowed afterwards, which settles
# two things.  The answer depends on the top eleven bits of the sample and nothing else — eleven being
# the vendored configuration's PNG_MAX_GAMMA_8 — so the table has two thousand and forty eight entries
# and a bucket spans thirty two values.  And all but sixty of those entries are the exact answer at the
# bucket's lowest value, scaled to eight bits and rounded.
#
# The sixty are the difficulty.  Each of them lands within a few thousandths of a rounding boundary and
# falls the other way, which is the reference's own fixed point arithmetic showing through rather than
# anything a formula fits — every candidate tried, by sample point and by scaling and by index, stops
# at the same one thousand nine hundred and eighty eight.  So what remains is to port the construction
# rather than to fit it, and until that is done this library gives the exact answer, which is the
# better one to hand a client as well as the easier one to write.

# Reversing sub-byte samples within a byte, for an interlaced image.
#
# This is the one transform whose result depends on where a pixel sits inside a byte rather than only
# on the pixel, and for an interlaced image that matters.  The reference spreads a pass across a
# full-width row *before* transforming it and then merges the result under a bit mask, so the reversal
# happens at the pixel's final position.  This library transforms the narrow pass row and spreads
# afterwards, so the reversal happens at its position within the pass.  Every other transform is
# per-pixel and agrees either way; this one does not.
#
# Closing it means adopting the reference's arrangement: expand the pass to full width, transform, then
# merge under a mask that accounts for the reversal.
