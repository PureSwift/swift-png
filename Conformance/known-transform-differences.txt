# A greyscale transparent colour compared against a row that has become colour.
#
# The transparency chunk of a greyscale image says only which grey is transparent; the red, green and
# blue fields of the structure it is reported in are never set and stay zero.  When the row has been
# turned into colour before the comparison happens, the reference compares against those three fields
# rather than against the grey — so a black pixel matches a transparency that names mid grey, and comes
# out as the background.
#
# This library compares the grey the chunk actually names, so a black pixel stays black.  Reproducing
# the other reading would mean treating fields the format never filled in as though they meant
# something.

# -- this library's own gaps, still to be closed ------------------------------------------------
#
# These are defects here, not there.  They are listed so the suite stays honest about what it is and
# is not checking, and each one is a piece of work rather than a decision.

# Sixteen bit gamma: closed, by porting the reference's segmented table.
#
# The reference never corrects a sixteen bit row sample exactly.  It builds a table whose input is
# the sample's top bits — coarsened by a significant-bits chunk, and capped at eleven bits (its
# PNG_MAX_GAMMA_8) when the samples are to be narrowed to eight — and, for the narrowing case, it
# builds that table backwards: walking the 256 possible outputs and finding the input at each
# boundary through the fixed-point reciprocal of the exponent.  That inverse construction is why
# roughly sixty of its two thousand and forty eight entries could never be fitted by any forward
# formula: they are not corrections of any input, they are boundaries, and the reciprocal's own
# rounding moves them.
#
# This library used to compute each sample exactly instead, and a long list of one-count
# differences sat here to say so.  Both constructions are now ported — WideGammaTable in
# Sources/PNG/Transforms/Gamma.swift, arithmetic step for arithmetic step, the quantized identity
# for an insignificant exponent included — and every sixteen bit gamma case in the sweep is exact.
# The exact computation survives where it always agreed: a sixteen bit image with no
# significant-bits chunk and no narrowing, where the reference's table is at full precision, and
# every single-value correction (map entries, backgrounds), which the reference itself computes
# exactly rather than through the table.


# Reversing sub-byte samples within a byte, for an interlaced image.
#
# This is the one transform whose result depends on where a pixel sits inside a byte rather than only
# on the pixel, and for an interlaced image that matters.  The reference spreads a pass across a
# full-width row *before* transforming it and then merges the result under a bit mask, so the reversal
# happens at the pixel's final position.  This library transforms the narrow pass row and spreads
# afterwards, so the reversal happens at its position within the pass.  Every other transform is
# per-pixel and agrees either way; this one does not.
#
# Closing it means adopting the reference's arrangement: expand the pass to full width, transform, then
# merge under a mask that accounts for the reversal.
