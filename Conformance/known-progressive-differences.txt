# -- this library's own gaps, still to be closed ------------------------------

bad-corrupt-zlib.png Not implemented here: the two libraries agree on what happens to a file whose compressed image data is corrupt — the client is warned, no rows are produced, and the walk carries on to the end — but not on what to call it. The reference summarises the failure as an ADLER32 mismatch and adds a second warning about the data left over; this library reports what the decompressor said. Closing it means finding the reference's mapping from a decompressor's fault to its own words, which is worth doing with the whole error corpus rather than one file.

over-image-data.png Not implemented here: a file carrying more scanlines than its header describes. Reading it a row at a time, the two libraries agree — both say so once, as the image ends. Pushed in, the reference says it differently and more than once: one "Extra compressed data in IDAT" and then an "Extra compression data in IDAT" for every further push that carries any, so what a client sees depends on how the bytes were divided. Closing it means pinning down which of the two wordings goes with which moment, which is worth doing against the whole error corpus rather than from this one file.
